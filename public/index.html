Getting started

                
ReStreamAir re-streams DASH/HLS sources as clean HLS you can play in any player. Create a Provider (a group of streams that share settings and credentials), add Streams under it, then hit play or copy the output URL.

                
    
                  
  1. Go to Providers → New provider.
    2. 
                  
  2. Open the provider, add a stream with its source URL (an .mpd or .m3u8). Paste the URL and pause — the panel probes it and fills in qualities, audio tracks and any DRM KIDs by itself. There is no Detect button and no type dropdown.
    3. 
                  
  3. Press Start, then Copy output URL and open it in VLC / a browser / an IPTV player.
    4. 
                

                
A .mpd stream must be started before its URL answers — the engine has to fetch and decrypt a few segments first. Until it's ready, /play returns 503 with a Retry-After and players retry on their own.

              


              

                
Providers & streams

                
Provider settings hold defaults shared by every stream under them: proxy, generic headers, downloader, and a provider script + accounts. A stream inherits these unless it overrides them.

                
    
                  
  • Proxy — set once on the provider; a stream's own Proxy field wins if filled, and Use proxy for scopes it to Script / Manifest / Media independently.
    • 
                  
  • Stream tuning (Playlist count, Keep count, Download ahead, Poll seconds, Playback delay) is per-stream, in the stream editor's DASH options — see below.
    • 
                  
  • All Streams view: bulk start/stop/delete, filter by provider and by Channels / Events / Manually added, and import channels or events from a provider script.
    • 
                  
  • Export / Import — the download icon on a provider card writes one JSON file with every setting, stream, account and the script's own source. It contains passwords in clear; treat it like a credentials file.
    • 
                

              


              

                
Stream tuning (DASH options)

                
These control the rolling window the engine keeps for a .mpd stream. The defaults suit most sources; reach for them when a player stalls.

                

                  
FieldWhat it doesRaise it when…

                  
Playlist countSegments advertised in the playlist. Minimum 3.Players buffer poorly or stall at the live edge.

                  
Keep countSegments kept behind the window before pruning.The logs show 404s for segments a player asked for — it fell behind and they'd already aged out.

                  
Download aheadHow far ahead of the playlist the engine fetches.The origin is slow and the engine can't stay ahead.

                  
Poll secondsHow often the MPD is re-read. Defaults to the manifest's own minimumUpdatePeriod, else 2.The logs show pollSlow — a poll cycle is overrunning its own interval.

                  
Playback delay (s)Holds playback that many seconds behind the live edge. 0 = live.You want a cushion against origin hiccups more than you want latency.

                  
Audio delay (ms)Lip-sync offset, positive or negative. Rewrites each audio segment's timestamps — not a re-encode.Audio drifts against video.

                  
EPG channel idExported as tvg-id in the M3U — how an external player binds guide data to this channel. Blank uses the stream id.You're pointing TiviMate, Kodi or Jellyfin at both the playlist and a script's EPG.

                  
Allow offline/static MPDAccepts a type="static" (VOD) manifest.The source is a recording, not a live feed — otherwise it's rejected.

                

                
Select more than one quality and the stream serves an HLS master playlist with one worker per representation, so Quality and Audio dropdowns appear in the player. Every track is selected by default.

              


              

                
Network & downloader

                
Headers come in buckets so a token only goes where it belongs: the provider's Generic headers apply everywhere, and each stream adds Manifest headers, Media headers and (for HLS) HLS key headers on top.

                
Downloader picks what actually fetches:

                
    
                  
  • native (default) — in-process libcurl, no subprocess per fetch. It pins HTTP/1.1, because some origins run a flaky HTTP/2 stack that drops mid-segment.
    • 
                  
  • curl / wget / aria2c — spawns that binary instead; Downloader params appends extra arguments (--retry 3, -x 8).
    • 
                

                
Proxies may be HTTP or SOCKS5 (socks5h://user:pass@host:port). Credentials embedded in the URL are used when the proxy challenges for them.

                
Tokens in the query string. Tick Append each stream's own Source URL query params to its segments when a CDN signs a token onto the manifest URL and expects it on every segment. The params are read from the URL that actually answered the poll, not the one you configured — some CDNs only sign the redirect target, where the configured URL has no token at all. For a fixed string that isn't part of any stream's URL, use the provider's Segment URL params instead.

              


              

                
Playback & output

                
Every stream is served at /play/<id>/index.m3u8, whatever produces it. The Input/output pipeline section chooses how:

                
    
                  
  • Internal remuxer (default) — no ffmpeg needed; downloads, decrypts and remuxes segments itself.
    • 
                  
  • FFmpeg modes — spawn a resident ffmpeg that reads the source and copy-remuxes to HLS, or pushes to SRT/UDP/TCP via the Output target.
    • 
                  
  • N_m3u8DL-RE — hands the source to that downloader instead.
    • 
                  
  • Direct source — /play 302-redirects to the origin rather than restreaming. The API-key gate still applies to the redirect.
    • 
                

                
Beside the player are two opt-in links: /direct/<id> streams a raw fMP4 tail down one never-closing connection (no playlist, no polling), and /download/<id> hands back whatever is currently buffered as a playable .mp4.

                
Segment URLs carry no upstream address. A live DASH playlist names its segments <rep>_<seq>.m4s and nothing else — the bytes are already downloaded and decrypted in memory before a segment is ever advertised, so there is no origin URL to leak to whoever holds the playlist.

                
Export playlist writes an M3U of every stream for VLC, Kodi or an IPTV app. It lists everything, but opening an entry doesn't start it — .mpd streams must be started here first.

              


              

                
Provider scripts & Protocol

                
A script is any .py / .sh / executable that owns login, session management, or DRM/key logic. It's invoked with flat key=value arguments and prints its output to stdout (logs/debug to stderr). See SCRIPTING.md for the full guide with worked examples.


                
Script actions are opt-in. Each provider declares which actions its script implements, as a checkbox grid in Provider settings → Script actions. ReStreamAir only ever calls the ticked ones — a script that only does channels is never handed a start it can't answer. A stream inherits its provider's set and can override it (including to nothing).


                
Common input (every action):
action=<name> bind= proxy= doh= worker= sessiondir=<dir> cookies=<file>, then user=/password= only when non-empty, then per-stream Script params (e.g. id=123). sessiondir/cookies point at a durable per-provider folder the script keeps its login in.


                
Values may be base64. A value containing whitespace, a quote, a backslash or non-ASCII — and always a password — is base64-encoded and prefixed b64:, so secrets never appear in ps and spaces don't split. URLs and ? & ; * stay plain (there's no shell). Decode every arg (strip a leading b64:); output you print is auto-detected the same way.

Timeouts: channels/events 60s, epg 120s, manifest 45s, cdm 60s, pipeline hooks 15–20s, lifecycle 20s; login/pair run in the background with none. Pipeline hooks fail soft — a hook that errors or times out is logged and ReStreamAir falls back to its built-in behaviour.

                
Channel/event import per item uses keys: Name, Mode (live/vod), SessionManifest, UseCdm, CdmType, Video, Audio, OnDemand, SpeedUp, Autostart, Start/End, RecordEvent, and ScriptParams — each also accepted lowerCamelCase. Re-running an import updates matching streams in place, matched by name. A logo is looked up by channel name and filled in if you haven't set one.

                
Imported streams have no source URL. The import fills in everything above but leaves the URL empty, so an imported channel only plays if it can resolve one — that means SessionManifest plus a working manifest action, or typing the URL in by hand afterwards.


                
Expected output — worked examples

                
The // comments below are explanation only. Your script must print valid JSON (no comments) to stdout — put logs/debug on stderr. ReStreamAir tolerates a few log lines before the JSON blob, and reads the first { … }.


                
channels — one entry becomes one stream under the provider:

                
{
  "Channels": [
    {
      "Name": "Channel One",     // stream name (also the match key on re-import)
      "Mode": "live",            // "live" or "vod"
      "ScriptParams": "id=101",  // passed to manifest/cdm/heartbeat for THIS stream
      "SessionManifest": true,   // fetch a fresh URL from `manifest` on every start
      "UseCdm": true,            // resolve DRM keys via the `cdm` action
      "CdmType": "widevine",     // hint only; ReStreamAir forwards all DRM it finds
      "Video": "best",           // preferred quality (optional)
      "Autostart": false         // start automatically after import (events use Start/End)
    }
  ]
}


                
manifest — a fresh, per-session source (Session manifest):

                
{
  "ManifestUrl": "https://cdn1.example.com/live/abc123.mpd",  // the source to stream from
  "Cdn": [                                                    // failover mirrors, tried in order
    { "Name": "cdn2", "ManifestUrl": "https://cdn2.example.com/live/abc123.mpd" }
  ],
  "Headers": {                          // sent per fetch category
    "manifest": { "User-Agent": "MyApp/1.0", "Authorization": "Bearer eyJ…" },
    "media":    { "User-Agent": "MyApp/1.0" }
  },
  "Heartbeat": {                        // keep the session alive (optional)
    "Url": "https://example.com/keepalive",
    "Params": ["id=101"],
    "PeriodMs": 300000                  // run the `heartbeat` action every 5 min
  }
}


                
cdm — clear keys for a protected stream. Print one pair per line, or JSON:

                
// simplest: one KID:KEY hex pair per line (KID and key are 32 hex chars)
c3d43de9ff5b5a45cdc9f4e7f177a1a5:11223344556677889900aabbccddeeff

// or JSON:
{ "keys": [ { "kid": "c3d43de9ff5b5a45cdc9f4e7f177a1a5",
              "key": "11223344556677889900aabbccddeeff" } ] }

              


              

                
DRM / keys

                
ReStreamAir is an IPTV restreamer, not a DRM client — it never runs a real Widevine/PlayReady/FairPlay CDM. For protected streams a script returns clear keys and the remuxer decrypts with them.

                
    
                  
  • Manual keys — paste KID:KEY hex pairs (one per line) in the stream editor's decryption box. These always win.
    • 
                  
  • Get keys via script — tick CDM keys in the stream's Script actions. When the stream is protected and no keys were pasted, ReStreamAir parses the manifest for every DRM detail (all KIDs, Widevine + PlayReady PSSH, HLS key URIs) and hands it to the cdm action, which returns clear KID:KEY pairs. The script always runs the license exchange itself — ReStreamAir has no embedded CDM, so challenge= is passed empty.
    • 
                  
  • Refine what's sent — the optional PSSH parsing and Init parsing actions let the script rewrite the PSSH or pull extra KIDs/PSSH out of the init segment before the cdm call.
    • 
                

                
Key output formats accepted: bare KID:KEY lines, --> KID:KEY, or JSON {"keys":[{"kid","key"}]}. This decrypts cenc (AES-CTR) directly; cbcs pattern encryption isn't supported.

              


              

                
Session manifest & heartbeat

                
When a source URL is short-lived (per-session/token), tick Session manifest (the manifest action) in the stream's Script actions. On every start the panel runs it and streams from the fresh URL it returns:

                
{
  "ManifestUrl": "https://…/live.mpd",
  "Cdn": [ { "Name": "cdn2", "ManifestUrl": "https://…" } ],
  "Headers": { "Manifest": { "User-Agent": "…" }, "Media": { … } },
  "Heartbeat": { "Url": "", "Params": "", "PeriodMs": 300000 }
}

                
CDN mirrors become failover sources, Headers apply per fetch category, and Heartbeat.PeriodMs auto-sets the heartbeat interval (which re-runs the heartbeat action that often to keep the session alive). The stream editor's Heartbeat (seconds) overrides it when non-zero.

                
manifest is also the recovery hook. When a fetch fails on the primary URL and every CDN mirror, the script is asked for a fresh one, which is saved and retried — inline for .m3u8 passthrough, in the background once a .mpd worker has needed two restarts in a row. Throttled to one refresh per stream per minute. So a token that expires mid-stream recovers on its own.

              


              

                
Monitoring & logs

                
The Server view streams live over SSE: input vs output bandwidth (per stream and all-time), active viewers per stream, host CPU/memory/disk, and one searchable row per playback connection.

                
The Logs view shows what each worker is doing, newest first, polled every 2s only while it's open. Filter by stream, level or run date, toggle Verbose for raw JSON, or jump straight to one stream's logs from the icon on its card. Per-stream Clear hides everything logged so far for that stream while leaving new activity visible.

                

                  
EventMeans

                  
manifestA manifest poll, with the URL that answered it.

                  
renditionsVideo/audio representations settled; the master playlist is ready.

                  
discontinuityA timeline splice was detected and marked in the playlist.

                  
pollSlowA poll cycle overran its own interval. Consistently slow means a longer Poll seconds or fewer segments per poll — not more polling.

                  
errorIncludes the origin's own response body when it sent one, so a 403 that explains itself (“limit of concurrent streams reached”) says so instead of showing only the status code.

                

                
History is written to logs/<date>.jsonl, capped at 8MB a day and rotated, keeping the newest 5 files.

              


              

                
Troubleshooting

                

                  
SymptomWhat to do

                  
/play returns 503 right after StartNormal — the engine answers immediately rather than blocking while the first segments arrive, and players retry. If it stays at 503 the stream never became ready: check Logs for the manifest fetch.

                  
Player stalls, logs show segment 404sIt's asking for segments that already aged out. Raise Keep count (and Playlist count), or Poll seconds if pollSlow also appears.

                  
Origin returns 403 and won't say whyIt usually does now — the error line carries the origin's own response body. Concurrent-stream limits in particular say so explicitly.

                  
Concurrent-stream limit trips with one stream runningA video+audio stream normally makes three concurrent manifest fetches (a director plus two workers). Tick Reduce manifest polling under DASH options to cut that to two.

                  
Origin returns HTTP 429, and the playlist stops advancingThe origin is rate-limiting this server by IP. Failed polls now back off automatically (they double, up to a minute, and start at 15s for an explicit rate refusal), so it will recover on its own once the origin relents — but it will keep tripping unless you also ask less often. Raise Poll seconds and tick Reduce manifest polling.

                  
Segments download but there's no pictureCheck Logs for a key mismatch — a segment whose KID matches none of your pairs is now reported instead of being decrypted with the wrong key. cbcs pattern encryption isn't supported at all; only cenc (AES-CTR).

                  
Audio drifts against videoSet Audio delay (ms), positive or negative, in DASH options.

                  
A VOD / recording is rejectedTick Allow offline/static MPD.

                  
Playback breaks in the browser onlyhls.js runs in debug mode — its full event log is in the browser console, no server logs needed.

                

              


              

                
Accounts & security

                
Panel accounts live in Settings → Accounts and come in two roles:

                
    
                  
  • Admin — full control.
    • 
                  
  • Viewer — read-only. Sees the panel, monitoring and logs; every write is refused with a 403. Enforcement is on the HTTP method, not a route list, so anything added later is read-only for viewers by default. Provider export is admin-only, since it embeds script-account passwords.
    • 
                

                
The last admin can't be deleted, and deleting an account ends its sessions immediately.

                
Sessions survive a restart. They're kept in state.json as SHA-256 hashes — never the token itself — so “remember me for 30 days” means 30 days, not “until the next restart”. Failed sign-ins are throttled per username and address: five free attempts, then a doubling delay capped at 15 minutes, answered with 429. That counter is in memory only, so nobody can lock an account out across restarts.

                
The panel speaks plain HTTP. On a trusted LAN that's fine. Anywhere reachable from the internet, put a terminating proxy in front of it — otherwise the sign-in form and the session cookie cross the network in the clear. The README has Docker, Compose-with-Caddy and systemd recipes.

                
Behind a proxy, set Trusted proxies (Settings). Untouched, every request appears to come from the proxy's own address — one “client” for the entire internet, which collapses the viewer counts, the connection table and the login throttle onto a single address, and leaves the session cookie without its Secure flag. Accepts loopback, private, any, or a list of addresses and CIDR blocks. Only then are X-Forwarded-For and X-Forwarded-Proto believed — untrusted, they're ignored outright, which is what stops a client forging its way past the throttle.

                
Your proxy also has to stop buffering: /api/events is an SSE stream open for the life of the panel and /direct/ never ends. Caddy: flush_interval -1. nginx: proxy_buffering off plus a long proxy_read_timeout.

              


              

                
Running the binary

                
On Linux, download the …-linux-x86_64.tar.gz release, extract, and run the launcher — not the raw binary:

                
tar -xzf restreamair-vX-linux-x86_64.tar.gz
cd restreamair-vX-linux-x86_64
./restreamair --port 8787 --bind 0.0.0.0

                
restreamair is a wrapper that points LD_LIBRARY_PATH at the bundled libs/ (so it works on distros that ship a different libxml2 soname). To update, replace the folder (or drop the new restreamair-linux over the old one).

                
Port resolves as --port, then $PORT, then the value saved in Settings, then 8787; bind address the same way. Both need a restart — a live listener can't rebind.

                
There is also a fully static restreamair-linux-static build with no library dependencies at all — but its statically linked TLS stack can't make outbound HTTPS requests, so use the bundled or dynamic build on anything that has to reach an origin.

                
Everything lives in the working directory: state.json (all config, including script passwords), runtime/ (segments and script sessions), logs/, and logo-cache.json.

              


              

                
API keys & CLI

                
    
                  
  • API Keys view — generate keys to require auth on playback; add ?key=… to the play URL, or send Authorization: Bearer <key>. The gate covers every playback route (/play/, /restream/, /proxy/, /direct/, /download/, /source/). With no keys defined, playback is open to anyone who can reach the port.
    • 
                  
  • Panel logins are separate — an API key never gets you into /api/*, and an admin account is not a playback key.
    • 
                  
  • Export playlist — one M3U of every stream, for VLC/Kodi/an IPTV app.
    • 
                  
  • CLI: restreamair cdmprobe mpd=<url> [script=<path>] prints the DRM challenge (KIDs/PSSH) and, with a script, the clear keys it returned — the quickest way to test a CDM script.
    • 
                  
  • CLI: restreamair dash --info <url> inspects a manifest without touching the panel; restreamair selftest runs the crypto known-answer vectors.
    •
